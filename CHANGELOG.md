## 2026-11-20

### Режим VLESS + REALITY + XHTTP + Vision

- Добавлен третий режим инбаунда `reality_xhttp`: REALITY поверх транспорта XHTTP (`"network": "xhttp"`, `xhttpSettings: {path, mode: "auto"}`) вместо голого TCP. Схему REALITY + TCP + Vision ТСПУ в 2026 году научился детектить по сигнатуре: серверы в этом режиме банили.
  - Ключи REALITY, short id, `dest` и serverNames общие с режимом `reality`, поэтому переключение между ними не перегенерирует ключи. Клиентам всё равно нужно заново импортировать ссылку: меняются `type` и `flow`.
  - Путь XHTTP генерируется случайным при первом применении (`xhttp_path`), его можно задать вручную. Одинаковый путь на всех установках был бы ещё одной сигнатурой.
  - Ссылка: `encryption=mlkem768x25519plus...&type=xhttp&path=...&mode=auto&flow=xtls-rprx-vision`.
- **Vision поверх XHTTP работает только с шифрованием VLESS.** Проверено на Xray 26.3.27 локальным сервером и клиентом:
  - без шифрования клиент падает с `XTLS only supports TLS and REALITY directly for now`;
  - с шифрованием `mlkem768x25519plus` (пара от `xray vlessenc`, вариант с X25519-аутентификацией) Vision работает: в debug-логе виден `XtlsPadding`, 5 МБ скачались без ошибок.
  - Пара ключей шифрования генерируется при первом применении (`vless_decryption`/`vless_encryption`) и перегенерируется вместе с ключами REALITY. Импортёр берёт `decryption` из существующего конфига и выводит из него клиентский ключ.
- В UI режим `reality` подписан как «REALITY + Vision (TCP)». Импортёр (`tools/import_xray_config.py`) распознаёт REALITY + XHTTP.
- Проверялось локально на Xray 26.3.27: сгенерированный панелью config.json проходит `xray run -test`. Ссылка из `build_vless_link`, переложенная в клиентский конфиг xray, проксирует HTTPS-запрос в обоих reality-режимах (`dest` = www.apple.com:443). На боевом сервере ещё не проверялось.

## 2026-11-07

### API для центрального управления несколькими серверами

- `/api/v1/*` с Bearer-токеном (`data/api_token`, показывается и перегенерируется на вкладке «Управление» → «Центральное управление (API)»). Токен не открывает HTML-панель, сессия панели не открывает API.
  - `GET /api/v1/status`: версии, статус xray, клиенты, почасовая история трафика, статистика по клиентам.
  - `POST /api/v1/xray/{start|stop|restart|apply}`: `apply` перегенерирует config.json и перезапускает xray, только если `xray -test` прошёл.
  - `POST /api/v1/update/{check|apply}`.
- Учёт трафика в байтах: в генерируемый config.json добавлены `api` (StatsService на `127.0.0.1:10085`, порт задаётся через `XRAY_API_PORT`), `stats` и `policy`. Раз в минуту stats.py читает и сбрасывает счётчики (`xray api statsquery -reset`).
  - В stats.json добавлены поля `up`/`down`/`daily_bytes`/`last_traffic_at` по клиентам и серверный ряд `hourly` за 14 дней.
  - На уже работающих серверах счётчики включатся только после «Применить конфиг» (или любого apply из панели) и перезапуска xray. До этого считаются только подключения.
- Проверялось локально: конфиг проходит `xray run -test` на Xray 26.3.27, StatsService отвечает на `statsquery`. Сквозной тест с центральной панелью проводился на временных данных.

## 2026-08-01 — 2026-08-02

### Разделение веб-интерфейса на вкладки

Панель была одной длинной страницей — сложные настройки (сервер, режим подключения, mTLS, клиенты, статистика, apk, пароль) и простые действия для клиента (скопировать профиль, скачать apk, инструкция) были вперемешку.

- Добавлены две вкладки: **«Клиенту»** (открыта по умолчанию) и **«Управление»**.
- «Клиенту»: блок «Моё подключение» (выбор своего имени + кнопка «Копировать профиль» + кнопка «Скачать v2rayNG.apk») и всегда развёрнутая пошаговая инструкция по установке v2rayNG.
- «Управление»: всё остальное — старт/стоп/рестарт сервера, режим REALITY/WS+TLS и его настройки (включая mTLS), управление клиентами, статистика подключений, загрузка/удаление apk, смена пароля панели.
- Переключение вкладок — на JS, без перезагрузки страницы и без новых роутов/логина.

### Починен баг с зависанием при загрузке apk

Загрузка apk-файла иногда обрывалась на мобильной сети (`ConnectionResetError`), а старый файл к этому моменту уже был удалён — в итоге панель оставалась без рабочего apk вообще.

- Загрузка теперь пишется во временный файл и подменяет старый только после полностью успешной записи.
- `OSError` (обрыв соединения, диск переполнен и т.п.) отлавливается — временный файл удаляется, старый apk остаётся нетронутым, пользователь видит понятную ошибку вместо зависания сайта.

### Починено реальное подключение через v2rayNG (self-signed сертификат)

После обновления xray-core на сервере (и, судя по всему, в самом v2rayNG) клиенты перестали подключаться — ни обычная `vless://` ссылка, ни JSON-конфиг с сертификатом не работали.

Причины нашлись две, обе подтверждены реальным тестовым подключением через сервер (не только валидацией схемы):

1. **`allowInsecure` полностью убрали из xray-core.** Раньше это поле разрешало доверять самоподписному сертификату сервера; теперь конфиг с этим полем движок просто отказывается загружать. Заменено на `pinnedPeerCertSha256` — отпечаток сертификата сервера, «пришпиленный» прямо в конфиг. Поскольку у `vless://`-ссылки нет места для отпечатка, для WS+TLS теперь всегда выдаётся полный JSON-конфиг (раньше — только при включённом mTLS).
2. **v2rayNG не распознавал вставленный JSON как конфиг.** Разбор кода v2rayNG (`parseCustomConfigServer`) показал: вставка из буфера считается конфигом только если в тексте есть одновременно `inbounds`, `outbounds` **и `routing`**. Последнего в нашем конфиге не было — добавлено пустое no-op поле `"routing": {"domainStrategy": "AsIs", "rules": []}`.

Заодно: убран бесполезный чекбокс «allowInsecure» из настроек (поле больше ни на что не влияет).

### Имя профиля в v2rayNG вместо метки времени

Импортированный профиль показывался в v2rayNG как голое число (`1785584568599`) — потому что v2rayNG берёт имя из поля `remarks` внутри JSON-конфига, а его не было.

- Новое поле в «Управление» → «Настройки подключения»: **«Название сервера»**.
- Имя профиля теперь `Название сервера — Имя клиента` (например, «Мой VPN — leb»); если поле не заполнено — просто имя клиента.

### Ссылка для клиентов без пароля панели

Добавлена возможность делиться клиентской частью (вкладка «Клиенту») без пароля от панели.

- Новый блок в «Управление»: **«Ссылка для клиентов»** — секретная ссылка вида `/c/<токен>`, кнопка «Копировать», кнопка «Перегенерировать ссылку» (старая сразу перестаёт работать).
- Ссылка открывает урезанную версию страницы: только «Моё подключение» и инструкция, без логина, без раздела «Управление».
- Токен — случайная строка (`secrets.token_urlsafe`), хранится в `settings.json`, сравнивается через `hmac.compare_digest` (защита от timing-атак).
- Ссылка общая на всех клиентов из списка (как и сам блок «Моё подключение»), а не персональная на одного человека.
